# Customer services pilot
Based on the successful physical one-boot pilot. The permanent Setup page is removed; account verification remains in the protected onboarding flow and sanitized metrics. The Monitoring tab presents live checks plus access to the complete Kuma console, not a claim of native feature parity. Kuma remains the underlying engine and preserves history, alerts and existing data. First-run Kuma account setup attempts to configure fixed appliance monitors; failures are reported without resetting credentials.

Private networking: prefer customer-owned Tailscale with MagicDNS/Serve and explicitly reviewed ACLs. No owner credentials, Cloudflare account, public Funnel or router port forwards. Pi-hole remains optional and is not enabled as network-wide DNS or DHCP automatically. The existing paired LAN gateway is not a substitute for customer tailnet access. Current laptop can keep operating; do not reimage to test these changes. New external integrations require separate acceptance and security checks.

## Media extension (experimental)
`scripts/pilot-media.py INSTANCE --soulseek --apply` is explicit customer consent to start one private generated Soulseek account, never reuse the owner's account. The slskd image is pinned to the upstream 0.26.2 manifest; API and network credentials are distinct. Only a dedicated empty share is mounted; customers choose material they have rights to share. No P2P listener is published automatically. Direct Jobbi Music search is wired; legacy downloader/import parity and actual first-login success are not verified. No accounts are created in CI. Never run on production.
Invidious needs three reviewed exact image references and the matching upstream Git source commit (manifest keys source_commit and images: invidious, companion, postgres). The private stack is generated with unique credentials and DB, local-only UI, no public companion port, no owner's endpoint. The internal fallback adapter, paired HTTPS route and real upstream playback are still pending. Do not accept mutable tags or third-party shared instances.
The media overlay is marked experimental and cannot be combined with exact recovery images. Do not assume backup/restore or vulnerability qualification.
## Remote access
Fresh laptop first boot attempts to install the official Tailscale package without enrolling. The opt-in `pilot-tailnet-enroll.sh` helper opens the customer's login flow, does not change DNS or accept routes, and refuses account switching. The existing private-access workflow still requires ACL review and full private origin transition; not yet one-click from the paired LAN UI. Pi-hole is not activated automatically; the existing isolated high-port DNS pilot remains available for a deliberate test. Do not set household DNS until client validation and rollback are ready.
