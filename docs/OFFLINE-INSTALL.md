# Phase 11 — offline application installation

From a dedicated reference instance installed from the exact clean release, after a backup has made the pinned restore helper available, run:

    python3 scripts/make-install-bundle.py INSTANCE --output /private/install-bundle --apply

This exports committed sources and exact container images only. Never use modified or untrusted reference images. Review upstream redistribution and licensing obligations. The kit contains no reference database, environment file or credentials. Keep private.

On a compatible Ubuntu host with Docker, Compose, Git, Python and an exact clean AIO release checkout already installed, prepare and verify independent storage and the boot guard, then run:

    python3 scripts/install.py --name home --data-root DATA_ROOT --apps EXACT_BUNDLE_APP_LIST --offline-bundle /private/install-bundle

The bundle selection and release must match. New credentials are generated by the normal installer; application sources and images are loaded locally. The exact created image inventory is checked before starting. Native account setup, private networking, backup timers and host qualification remain separate. Pi-hole is excluded from this first bundle path. This is offline application provisioning, not a disconnected Ubuntu OS installer; the original USB and host prerequisites still need compatible installation media. External app functions may require Internet. Never treat checksum verification as authenticity or scan clearance.
The guided `setup-customer.py` also accepts `--offline-bundle` with its normal data and backup roots and --apply. It requires preinstalled host prerequisites, skips automatic Tailscale download when offline, and omits network update checks. The fresh-install CI workflow checks distinct credentials and local dashboard/Kuma reachability; a fully disconnected OS and host-prerequisite installation remains future qualification.
## Private disconnected installer media

On a connected Ubuntu Server 24.04 amd64 preparation machine, use a **full, clean Git checkout** of the release. Create the exact application bundle above first. Use the standard authenticated Ubuntu package sources and refresh package indexes. Install the builder dependencies with `sudo apt-get install dpkg-dev xorriso openssl`.

    python3 scripts/offline_media.py /private/install-bundle --out /private/host-media

This includes the reviewed AIO commit, application archives and the Ubuntu package dependency closure. Keep the payload private and verify redistribution rights. Use the seed generator with the normal hardware-specific arguments and add `--ubuntu-iso ORIGINAL.iso --iso-sha256 VERIFIED_OFFICIAL_SHA256 --offline-media /private/host-media`. The output directory contains the customized ISO and SHA256SUMS. Check its checksum before writing it to an identified spare USB drive using a trusted imaging application. Writing the USB replaces its contents.

On the appliance, select the approved OS disk interactively. Keep the prepared data and backup filesystem UUIDs available for first boot. The offline seed verifies the payload before copying it, installs dependencies from the local package repository and uses the bundled Git revision and application images. Remote enrollment and online version checks are deferred. The ISO, local repository, installed files and subsequent backups need separate capacity planning. Package versions follow the authenticated preparation snapshot; retain the manifest and packages to reproduce that payload. The disconnected target-container drill verifies package installation; complete the interactive installer, firmware boot and first-boot sequence on a disposable VM or appliance before commercial delivery.
