# Phases 12, 13 and 15 — private management

The owner Customers page supports search, health filters, refresh, recent activity, and an explicit private JSON export of visible appliances. It never retrieves customer files or credentials or opens remote shells. Keep exported fleet records private.

On a customer appliance, the original non-root operator can launch `python3 scripts/manage-web.py INSTANCE` and use a trusted SSH tunnel `ssh -N -L 17994:127.0.0.1:17994 OPERATOR@APPLIANCE`. Open http://127.0.0.1:17994 and enter the temporary session code. Never publish this management listener, including through Tailscale Serve. The customer chooses whether to download/share a sanitized report. Application restart only targets an existing running single application container from a fixed allowlist; it cannot start arbitrary services, databases, alter files, pull images, or remove containers. Backup and upgrade holds prevent restarts. Expect an interruption. CLI equivalent: `python3 scripts/app-manager.py INSTANCE restart --app monitor` (preview), add --apply only after coordination. The everyday customer dashboard remains read-only. This is not a general remote administrator or app store.

Optional automatic private monitoring: `python3 scripts/configure-monitors.py INSTANCE --username owner` previews missing fixed internal app targets after customer Kuma login. Add --apply to create only missing HTTP reachability monitors. Existing monitor names, settings and notification channels are not edited; no arbitrary external URLs are accepted. This is not functional application acceptance, and the actual pinned Kuma integration still needs a test.
